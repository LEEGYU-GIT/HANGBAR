# HANGBAR M0 시험 제작 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 설계 §11의 위험 7가지(투명 오버레이·클릭 통과, 바탕화면 아이콘, 한글 입력, 두 PC 동기화, MSIX 포장, 자원 사용, 창 지형)를 실제 Windows에서 확인하고 결과를 기록한다. 이 결과로 M1 이후 계획을 쓴다.

**Architecture:** Godot 4 .NET(C#) 앱이 모니터마다 투명 오버레이 창을 띄우고, Win32·Shell COM으로 지형을 읽는다. 판단 로직(좌표, 클릭 통과, 전체 화면, 창 가장자리 자르기, PKCE, 재연결)은 Godot에 의존하지 않는 `Hangbar.Core` 라이브러리에 두고 xUnit으로 테스트한다. 실시간 중계는 Cloudflare Worker + Durable Object(TypeScript, Vitest)다.

**Tech Stack:** Godot 4.x .NET 최신 안정판(시작 시 정확한 버전을 결과 문서에 기록), .NET 8 SDK, xUnit, Node.js 22, Wrangler, `@cloudflare/vitest-pool-workers`, `jose`, Supabase(Auth만), Windows SDK(MakeAppx, SignTool, WACK).

**Spec:** `HANGBAR/docs/superpowers/specs/2026-11-22-hangbar-design.md` (제품 요구사항: `HANGBAR/docs/PRD.md`)

## Global Constraints

- Windows 10/11 x64만 대상.
- 다른 프로세스에 코드 주입 금지. 전역 훅(SetWindowsHookEx, LL 훅 포함) 금지. 커서는 `GetCursorPos` 조회만 쓴다.
- 폴더 이름·경로, 대화 내용은 로그·파일·네트워크에 남기지 않는다. 로그에는 개수와 길이만.
- 창 제목과 창 내용은 읽지 않는다.
- Godot 렌더러는 Compatibility(OpenGL).
- 오버레이 창 크기는 모니터 영역보다 높이 1px 작게.
- 클릭 통과 조회 주기: 커서가 캐릭터 근처면 33ms, 멀면 100ms, 숨김이면 조회 안 함.
- 전체 화면 판정은 1초마다.
- 자원 목표(실측 후 확정): 보통 상태 30fps 상한, CPU 평균 2% 미만, 메모리 200MB 미만. 숨김 상태 그리기 0.
- 창 지형 조회: 캐릭터가 올라탄 창 200ms, 나머지 1초.
- Durable Object는 SQLite 저장소 클래스(`new_sqlite_classes`)로 만든다(무료 플랜 조건). WebSocket Hibernation API(`ctx.acceptWebSocket`)를 쓴다.
- Supabase 토큰은 JWKS(`<SUPABASE_URL>/auth/v1/.well-known/jwks.json`)로 검증하고, issuer `<SUPABASE_URL>/auth/v1`, audience `authenticated`.
- 로그인 루프백 포트 후보: 53682, 53683, 53684 (차례로 시도).
- 다우메신저 시제품·Sure-Mate의 코드와 그림은 쓰지 않는다.

## Review Focus

1. **DPI 배율이 다른 모니터 두 개(100% + 150%)** — 오버레이·아이콘·창 가장자리 좌표가 모두 실제 위치와 맞아야 한다. → Task 2(좌표 테스트), Task 6·7 수동 확인.
2. **실행 중 모니터 연결·해제, 해상도 변경** — 오버레이 창이 새 배치에 맞게 다시 만들어져야 한다. → Task 2 `MonitorLayout.Diff` 테스트, Task 3 수동 확인.
3. **탐색기(explorer.exe) 재시작** — 아이콘 읽기가 실패해도 앱이 죽지 않고 작업표시줄·화면 아래 가장자리만으로 계속 돌아야 한다. → Task 6 `IconReadResult` 실패 경로 테스트와 수동 확인.
4. **작업표시줄이 왼쪽·위쪽이거나 자동 숨김** — 바닥 판정이 맞아야 한다. → Task 7 `TaskbarFloor` 테스트.
5. **네트워크 끊김·토큰 만료** — 재연결이 지수적으로 늦춰지며 이어져야 하고, 만료된 토큰은 서버가 거절해야 한다. → Task 9(서버 거절 테스트), Task 11 `ReconnectBackoff` 테스트.
